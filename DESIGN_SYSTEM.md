# Essence Design System

## Design Intent

Essence should feel like a quiet thought environment, not a software dashboard.

The visual system should communicate:

- calm
- clarity
- focus
- editorial taste
- low cognitive load

Essence is **not** a Material app, but it should borrow the parts of Material that improve usability and consistency.

## Core Direction

The right formula for Essence is:

`editorial visual language + Material-grade interaction discipline`

That means:

- visually warm, quiet, and typographic
- structurally clear and consistent
- interactive without feeling system-heavy

## What To Keep

These are core to the Essence identity and should stay:

- serif-led editorial hierarchy for major titles and reading moments
- warm paper-toned backgrounds instead of cool neutral UI grays
- restrained, low-elevation surfaces with thin borders
- generous whitespace around reading and writing content
- simple, calm metadata styling
- centered writing column and long-form reading posture
- low-chrome interface with minimal visual noise
- a writing-first layout where content is always more important than controls

## What To Borrow From Material

These are worth keeping or strengthening because they improve usability:

- strong spacing discipline and component alignment
- consistent focus states and keyboard accessibility
- predictable interaction states: default, hover, active, disabled, selected
- responsive layout logic that scales cleanly from desktop to smaller screens
- clear navigation hierarchy
- coherent motion principles for entering, leaving, and reordering content
- reliable affordance patterns for buttons, inputs, menus, and selection

## What To Avoid

These would pull Essence too far toward generic app design:

- FAB-heavy composition as a dominant pattern
- overly rounded, bubbly controls everywhere
- colorful status language and bright brand-accent overuse
- heavy shadows, floating cards, or layered elevation as the main visual structure
- stock app-bar and utility-shell styling that overwhelms the content
- dense dashboard layouts
- generic productivity-tool chrome that feels interchangeable with Material-based SaaS apps

## Visual Principles

### Typography Leads

Typography should carry the emotional weight of the product more than shapes or color.

- use serif type for major page titles, note titles, and key reading moments
- use sans-serif for controls, metadata, navigation, and utility text
- keep hierarchy clear but never theatrical
- avoid oversized display moments that overpower the workspace

### Paper Over Plastic

Surfaces should feel like paper, not layered components.

- prefer flat fills and 1px borders
- use elevation very sparingly
- rely on tone shifts before shadows
- keep interface surfaces close in value so content remains primary

### Quiet Utility

Controls should support the work without becoming the work.

- use compact icon buttons
- keep metadata visually soft
- avoid turning every action into a strong call-to-action
- reserve strong contrast buttons for rare, important actions

## Interaction Principles

### Selection

Selected states should feel precise and calm.

- use soft surface changes and border refinement before bold fills
- keep active nav states obvious but understated
- use the focus blue primarily for accessibility and input focus

### Motion

Motion should be subtle and purposeful.

- short fades and small positional shifts are enough
- avoid springy or playful movement
- animate structure changes, not every micro-interaction

### Input Behavior

Editing interactions should feel stable and distraction-light.

- preserve layout while typing
- avoid jumpy controls and changing chrome
- keep writing tools available but visually secondary

## Component Guidance

### Navigation Rail

- architectural, quiet, and structured
- should feel like part of the workspace frame
- active state should be clear without looking like a mobile app dock

### Top Bar

- low emphasis
- should frame context, not compete with the page title
- action groups should be visually tidy and compact

### Note Cards

- use a limited set of card types with clear purpose
- standard cards should be compact and scannable
- featured cards should earn their scale through content importance
- metadata should follow a repeatable pattern

### Editor

- writing area should remain the visual center of gravity
- editing controls should recede until needed
- block chrome should support structure, not distract from reading

## Color Guidance

- default palette should remain warm and near-monochrome
- black should be used sparingly for emphasis
- blue should stay reserved for focus, caret, selection, and precise interaction feedback
- avoid introducing multiple accent colors unless a future feature truly requires them

## Essence Test

If a new UI decision makes the app feel more like a generic productivity workspace than a premium thought environment, it is probably wrong.

The target feeling is:

`quietly premium, deeply usable, and centered on thought.`
